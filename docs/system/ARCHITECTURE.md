# Nullherz System Architecture Reference

**Source of truth:** reverse-engineered from the workspace code on 2026-07-20; refreshed 2026-07-21 (master EQ stage, async track hydration, cue-bus summing, live capture, needle-view lanes, tolerance-gated golden render); re-verified 2026-07-22 on branch `fix/dsp-correctness` (compressor dB→linear un-inversion, fractional-delay direction fix, boot library auto-scan disabled + folder monitor made sequential/idempotent).
**Scope:** every crate and sidecar in the workspace, the runtime data flow, wire protocols, and on-disk state.

This document describes *what is actually in the tree*, as opposed to the strategy and status documents which describe intent and maturity. When this document and the code disagree, the code wins — please update this file in the same PR.

Key invariants observed in code:

- **Node vs. buffer address spaces**: nodes and audio buffers (graph edges) live in *separate* index spaces — `MAX_NODES = 128` processors, `MAX_BUFFERS = 240` virtual buffer slots (`nullherz-traits/src/execution.rs`). A stereo console needs ~2 buffers per strip stage, so 4 decks × 8 stages × 2 channels plus buses and master already exceeds the old 64. Measured headroom (2026-07-28): the bootstrapped 4-deck console occupies **34 nodes but a highest index of 57**, because the allocator leaves gaps — the practical ceiling is index-bound, not count-bound, so budget against 57/128 rather than 34/128 when adding per-deck FX inserts. The `IdAllocator` hands out node IDs and buffer IDs from the two spaces independently; `GraphTopology.virtual_to_physical` is sized `[u32; MAX_BUFFERS]`. Out-of-range buffer indices are **rejected, loudly**, at three layers: `TopologyManager` refuses the command (conductor, off-thread), `GraphCompiler::compile` fails with `ConfigurationError`, and the RT-side `TopologyCoordinator` drops the mutation under a `debug_assert` (dropping is safe; clamping would alias a buffer another edge owns). Buffer ids are carried as the **`BufferId` newtype** (serde-transparent u32) through `NodeRouting` and `virtual_to_physical`, so comparing a buffer id against `MAX_NODES` is a compile error, not a review item. The crossfade-override sentinel (`block_x_map` cells = `MAX_BUFFERS + k` in a `u8`; requires `MAX_BUFFERS + MAX_CROSSFADE_BUFFERS ≤ 255`, enforced by a const assert) is encoded and decoded **only** through `BufferSlot` — the serial executor and worker pool share that single split point.
- **Planar sample buffers**: decoded samples are stored planar — channel *c* occupies `buffer[c*frames .. (c+1)*frames]` — and `SampleMetadata.total_samples` means frames *per channel* (`channels` is serde-defaulted for old libraries). `SamplerVoice::process_block_planar` advances its playhead in frames and renders each channel from its own plane (mono sources repeat channel 0), keeping the 4-wide SIMD interpolator valid on consecutive elements. The analysis worker analyses channel 0 only and preserves layout metadata; crop/time-stretch edits map per plane; decode overrides stale interleaved-era layout metadata on hydration.
- **Targeted commands**: `PerformanceCommand`s are BROADCAST to every node by the engine's command dispatch, so every processor arm must match its own address (`node_idx == self.id`, `target_id == self.id`). Untargeted matches caused cross-deck havoc four separate times (PlayNode armed every sampler; JumpToHotCue/SetLoop/SetSlipMode yanked all decks); a regression test pins per-deck isolation.
- **DJ transport semantics**: `StopNode` PAUSES (voices deactivate, position and buffer held); `PlayNode` resumes a paused voice of the CURRENT source (`Arc::ptr_eq` guard) or triggers fresh; `AddSource` clears every voice so neither a playing nor a paused voice can survive a track load. Hot cues persist three ways on `SetHotCue`: registry metadata, library row, and an `UpdateMetadata` push to the live node.
- **RAW by default**: `LoadTrackToDeck` emits the source plus the deck's tempo mode, and nothing else. Tempo-matching (`Core::SetBpm` + the sampler's `PARAM_QUANTIZE` phase-lock path) and harmonic pitch shift (the KeySync node) are each gated on a per-deck latch — `MixerManager::sync_decks` / `key_sync_decks`, set by `PerformanceCommand::SetDeckSync` / `SetDeckKeySync` — and both are OFF by default. Groove transfusion rides the SYNC latch. `CommandHandler` applies the latches *before* `translate_command` reads them, so pressing SYNC and loading in the same batch takes effect on that load. Releasing KEY re-centres the node at 0 semitones rather than merely ceasing to update it. With both latches off the library facet lookup is skipped, so a RAW load never takes the library mutex. Previously all of this fired on every load with no way to decline: the key shift measured **−5 semitones** toward a master key hardcoded to C, and the SYNC button that appeared to control it sent `SyncDecks`, which the orchestrator matched and discarded. Pinned by `conductor/tests/raw_mode_test.rs`.
- **Harmonic reference**: KEY shifts toward the track on `MixerManager::active_master_deck` (moved there from `Conductor` so translation reads console state from one place). `harmonic_shift` returns **0 semitones whenever the reference is unknowable** — no master track, no analysed key on either side, or the deck IS the master — because assuming C is what transposed unanalysed material. The reference is not constant, so loading onto the master deck or moving master re-aligns every KEY-latched deck via `realign_key_latched_decks`; `SetMasterDeck` is therefore applied in the pre-translation pass alongside the latches, since `handle_core_command` runs on the already-translated stream (a `debug_assert` there catches a future path that skips the pre-pass). Both helpers take an already-locked `&LibraryDatabase`: `parking_lot::Mutex` is not reentrant, so re-locking on the command path would deadlock rather than fail visibly.
- **Async track hydration**: `LoadTrackToDeck` never decodes on the tick thread — a full-track decode inline blocked every queued command (including the user's Play) for seconds. The decode runs on a named background thread (`hydrate-<id>`); `hydration_pending` dedupes double-clicked loads; the engine no-ops `AddSourceFromRegistry` while the registry misses and the sampler's `pending_play` holds an early Play; `tick()` drains completions and re-drives `LoadTrackToDeck` for every deck still mapped to that sample. Thread-spawn failure falls back to the inline decode rather than leaving the deck silent.
- **UI node binding**: the inspector resolves every node id by NAME from the telemetry node map (`get_node_id -> Option`); a missing name skips the command. Hardcoded indices and the old `unwrap_or(0)` fallback silently redirected at least five controls at deck A's sampler.
- **Sample-accurate commands**: `StandardKernel::execute` splits each period into sub-blocks at command timestamps, drains same-timestamp batches, and carries over future-dated commands (`pending_command`) — bounded by `MAX_COMMANDS_PER_BLOCK`.
- **O(1) topology swap**: the RT thread only ever executes `TopologyMutation::SetTopology` as an `Arc` pointer swap; Kahn's algorithm runs in `TopologyManager` off-thread. Regression-tested (`test_rt_topology_commit_is_no_op`).
- **Signal transparency at unity** (measured 2026-07-29, `conductor/examples/probe_signal_quality.rs`; 997 Hz, one deck, everything at unity). **THD+N is 0.00044% (−107.1 dB) against an analyser floor of 0.0000183% (−134.7 dB).** There is no non-linearity in the path at all — the worst harmonic is −152 dBc — and the entire residual is one node's f32 arithmetic noise (see the isolator entry below). Pinned by `conductor/tests/signal_transparency_test.rs`; the analyser and its tone generator are the shared contract in `audio_dsp::measurement`. Four findings, of which the first two were real defects, the third was the measurement, and the fourth is inherent:
  - **`SummingProcessor` shipped `soft_clip: true`.** `tanh()` is a WAVESHAPER, not a limiter — it distorts in proportion to level rather than waiting for a threshold, and it was on all **seven** summing nodes although the recorded intent was a "musical master" ceiling on the master bus alone. The console already has a real ceiling there (summing → `MASTERING_EQ` → **LIMITER** → out), so this was a second, undefeatable one in front of the first. Measured **THD+N 1.234% at −6 dBFS**. Studio converters sit at 0.001–0.01%; the audible threshold on music is ~0.1%. Param 1 re-enables it for anything that genuinely wants saturation.
  - **`StereoUtilityProcessor` applied a constant-power PAN law to a stereo signal**, costing **−3.01 dB at centre** on every deck. Constant-power is correct for placing a *mono* source in a stereo field; on already-stereo material it is just attenuation. Replaced with a balance law (unity at centre, never boosts).
  - **The residual 0.046% (−66.7 dB) was the measurement, not the console.** With the waveshaper gone the probe still read 0.046%, identically at −6 and −40 dBFS. Level-independence rules out any saturating non-linearity and points at something structural, so the crossover re-sum, the mastering EQ, the limiter and the coefficient ramps were each suspected in turn. None can account for it (`conductor/examples/probe_thd_bisect.rs`): driven standalone at unity the mastering EQ, the limiter and the gain stage are bit-exact identity, and the isolator's real residual — invisible until the analyser was rebuilt, see below — is 0.00045%, a hundredfold too small. **The tone generator was the source.** `probe_signal_quality` built its stimulus as `(i as f32 * freq * TAU / SR).sin()`; that argument grows without bound with `i`, and an f32 ULP grows with it, so the "pure" sine carries phase noise proportional to playback position — 0.0060% at sample 0, 0.0155% at 16_384, **0.0460% at 65_536**, 0.0911% at 131_072. The probe settles 256 blocks (65_536 samples) before capturing, so it graded the console on the dirtiest part of the file. Phase noise is broadband and scales with the signal, which is exactly why it presented as a level-independent residue and mimicked a structural fault. (Those four figures are as the then-current Hann analyser read them; the effect is real broadband phase noise, not leakage, so the rebuilt analyser reads it within a few percent of the same values.) The generator now accumulates phase in f64 and wraps it into `[0, TAU)`; the measured THD is flat at the instrument floor at every offset. **No DSP changed by any of this** — the golden master render is byte-identical.
    - The control that would have caught it is the one the probe now takes: the analyser floor measured on **the same window of the same buffer** the console is graded on. A control taken from sample 0 validates the analyser but not the *stimulus*, and comparing a sample-0 control against a sample-65_536 measurement compares two different tones and charges the difference to the mixer.
    - **The analyser was also the ceiling.** It used a Hann window needing a ±24-bin fundamental exclusion to reach a −86.8 dB floor — i.e. it bought Hann's −31 dB sidelobes off with exclusion width, which is the "widen the window until the residue disappears" move frozen into a constant. At that floor *every* node measured "at the floor" and the console's real residual was invisible. Now a 7-term Blackman-Harris window at ±8 bins: a **narrower** claim about what counts as signal and a floor of **−134.7 dB**, 48 dB lower. The floor is now set by `SimdFft`'s f32 arithmetic rather than by leakage — verifiable because it is flat across FFT sizes, which `test_floor_is_arithmetic_limited_not_leakage_limited` pins. An f64 FFT would reach ~−153 dB (where f32 sample storage takes over) and is not worth it while the quietest thing measured sits 28 dB above.
    - Consequence for the tests: the console transparency tolerance is now an **absolute** 0.005% limit, not a multiple of the floor. A floor multiple was the right shape when the floor was above everything the console did; with the floor 28 dB below the console's real residual it would demand the console be quieter than physics allows.
  - **`DjIsolator` is the console's entire THD+N residual, and it is arithmetic noise, not distortion.** Driven standalone at unity it measures −107.2 dB against the console's −107.0 dB; `Gain`, `MasteringEq` and `StereoUtility` are all bit-exact identity. The residue is broadband, concentrated at 3–103 Hz, with no harmonic content (worst harmonic −152 dBc). Mechanism: in Direct Form II Transposed the state is dominated by `y·a1`, so state magnitude tracks the band's *output* level; at 997 Hz the MID band passes at −0.17 dB, so its `HP300²` pair carries full-scale state and rounds at full-scale ULP, which the near-DC 300 Hz poles then shape up. Measured cost curve for f64 state (`conductor/examples/probe_analyser_resolution.rs`): MID's `HP300²` alone (2 of 8 biquads) → −122.4 dB; all four 300 Hz stages → −129.6 dB; all eight → −150.5 dB. **Left in f32 deliberately**: −107 dB relative at −6 dBFS is −113 dBFS absolute, 17 dB below the 16-bit floor and below every DAC's own THD+N, so it is inaudible and the fix would spend f64 SIMD lanes on a per-deck node. Note the ranking is frequency-dependent — at 100 Hz the LOW band would pass the signal and dominate instead — so acting on this needs the frequency sweep first.
  - **`DjIsolator`'s band re-sum: measured across frequency 2026-07-30, and it is a non-issue** (`conductor/examples/probe_frequency_response.rs`, pinned by `audio-dsp/tests/isolator_response_test.rs`). The 3-way split is `LOW = LP300²`, `MID = HP300²·LP3000²`, `HIGH = HP3000²`; the high band never passes through the 300 Hz section, so these are not a nested pair of LR splits and nothing structurally guarantees reconstruction. That was the standing suspicion. **Swept 30 Hz – 20 kHz, the worst deviation is −0.115 dB (at ~400 Hz and again ~2.3 kHz)** — inaudible, and the error is second-order because `HP3000²` has already removed the signal everywhere `HP300²` deviates from unity.
    - The textbook nesting (`HIGH = HP300²·HP3000²`) was swept alongside for comparison and is **not uniformly better**: it carries the same ~0.11 dB dip at 393 Hz and only wins above 700 Hz, where it converges to 0.000 dB against the shipped structure's −0.065 to −0.115. Worst case is a wash (−0.111 vs −0.115 dB). So the structure stays as it is, and the test bounds the *consequence* (±0.30 dB) rather than enforcing a topology — a dropped band or mis-ordered cascade reads as dB, not tenths, and was mutation-verified at −1.488 dB.
    - Note the crossover frequencies are declared **twice**, once in scalar `DjIsolator` and once in SIMD `DjIsolatorStereo`. That duplication is guarded: `test_dj_isolator_stereo_matches_two_scalar_bitexact` fails immediately if they diverge (verified by mutation).
  - **The isolator runs unconditionally on every deck** — 8 biquads per block whether or not anyone touched the EQ, the same "cost nobody asked for" pattern as the `tanh()` above and KeySync's 21 ms. Bypassing at unity gains would give a bit-exact console *and* save the CPU, but it is **not** safe as a per-deck knob state: the LR re-sum is allpass, so a bypassed deck mixed against an engaged one sums flat phase against rotated phase, and on a DJ console that is two copies of one track or kick-on-kick — the correlated case where it combs. Would need all decks to switch together. Not attempted; the phase argument is from the structure, not measured.
  - Total gain error at unity went **−9.10 dB → −6.09 dB**, and console peak with four decks **0.5322 → 0.9656** — the mix had been running ~9 dB conservative. The remaining −6.09 dB now accounts for exactly: **−6.02 dB** master crossfader at centre on a LINEAR law, plus the **−0.065 dB** isolator re-sum above.
  - **Crossfader curve: now a real control, RESOLVED 2026-07-30.** `curve` was always documented "0.0 = Linear, 1.0 = Power" but implemented as `if curve > 0.5 { constant-power } else { linear }` — a two-position switch where 84% of the knob's travel did nothing, and the default of `0.5` landed exactly on the boundary so the shipped law was selected by a comparison operator rather than by anyone. It is now a **continuous blend of the two gain laws**, so every intermediate value is a real intermediate law. Blending the gains rather than switching between them keeps the control monotonic — a threshold would click when a curve automation crossed it. The law also existed as two independent copies (scalar and SIMD paths); one definition now serves both, since a fix applied to one would have silently diverged from the other depending on block size.
    - **Default is now constant power** (`curve: 1.0`): −3.01 dB per side at centre, the hardware convention, because two *uncorrelated* tracks then sum to unity power and that is the normal DJ case. Linear (−6.02 dB, correct for correlated material) remains one `SetParam` away. Total gain error at unity is accordingly **−6.09 dB → −3.08 dB**, which decomposes exactly as −3.01 (crossfader at centre) + −0.065 (isolator band re-sum). Note that no crossfader law gives 0 dB at centre — a centred crossfader is *supposed* to attenuate each side, so the residual is correct behaviour rather than a remaining defect.
    - Golden master regenerated for this change: **L peak 1.87e-1 (−14.6 dBFS) rms 6.62e-2 (−23.6 dBFS); R peak 1.86e-1 (−14.6 dBFS) rms 6.60e-2 (−23.6 dBFS)** — consistent with the pure ×1.414 level change and nothing else. **A human listen is owed.**
    - **Headroom consequence, unresolved:** the +3 dB moved the smoke run's peak master level **0.9353 → 1.0002**, i.e. four decks playing simultaneously now reach the master limiter's 0 dBFS brickwall instead of sitting 0.58 dB under it. The limiter is doing exactly its job (the 0.0002 overshoot is float rounding, 0.0017 dB) — but the *default* console now engages its ceiling on ordinary material, where it previously did not. That is a gain-staging decision, not a defect, and deliberately **not** papered over with a compensating trim: an output gain added to hide a level change is the same move as the constant-power pan law this console already had to remove. Either the deck faders want a lower default, or four decks at full is simply a loud scenario. Needs a call.
  - **Frequency response is flat to ±0.056 dB, 40 Hz – 16 kHz** (measured 2026-07-30, `conductor/examples/probe_frequency_response.rs`; full console at unity, one deck). Absolute reading is −3.041 dB mean — the crossfader at centre plus the isolator's re-sum — so what matters is the RIPPLE about it, and the whole span is −3.010 to −3.097 dB. Studio-flat specs are typically ±0.5 dB; this is an order better. The only structure in the curve is the isolator's crossover regions (see its entry below).
  - Idle noise floor is **−400 dBFS** (true digital silence). Still not measured: phase/group delay, stereo imaging, intermodulation, and behaviour across sample rates.
- **Resampler quality at non-unity rates — FIXED 2026-07-30** (`audio-dsp/src/resample.rs`; measured by `conductor/examples/probe_resampler_quality.rs`, scoped by `probe_resampler_candidates.rs`, pinned by `audio-dsp/tests/resampler_quality_test.rs`). This was the system's dominant fidelity limit and it was invisible for a structural reason: at rate 1.0 the playhead lands on whole samples, the interpolation fraction is zero and the interpolator returns an input sample verbatim. That is *why* the console measured −107 dB, and a tempo-synced deck is essentially never at rate 1.0.

  THD+N at a realistic tempo ratio (+2.5% — a fractional phase with a long period):

  | source | Catmull-Rom (was) | Sinc 16-tap (now) |
  | ---: | ---: | ---: |
  | 997 Hz | 0.0026% (−91.8 dB) | 0.0018% (−94.9 dB) |
  | 5 kHz | 0.36% (−48.9 dB) | 0.0018% (−95.0 dB) |
  | 10 kHz | **3.56% (−29.0 dB)** | **0.0023% (−92.8 dB)** |

  **+64 dB at 10 kHz.** The audible threshold on music is ~0.1%, so the old cubic was 35× past it; the new kernel is 33× below it. Pitch-up aliasing went from **0.0 dB (a full-level fold, the loudest thing in the output) to −90.9 dB** at rate 2.0.
  - **No polynomial kernel could have fixed this.** Measured across the family at 10 kHz: linear −22.2 dB, Catmull-Rom −29.0, true 4-point Lagrange −33.6, 6-point Lagrange −43.7, cubic B-spline −46.2 (with −2.5 dB of passband droop). Polynomial interpolators have poor stopband rejection near Nyquist and the whole family *degrades with frequency* — spread from 997 Hz to 10 kHz is 62.8 dB for Catmull-Rom versus 2.1 dB for the sinc. **Flatness across frequency is the property that was bought, not the peak number**, and `test_resampler_quality_is_flat_across_frequency` is what states it.
  - **One kernel does both jobs.** For a stretch `s`, `h_s(u) = (1/s)·h(u/s)`: evaluating the same table at `u/s` scales the cutoff to `fc/s` and widens support to `s·TAPS` source samples, which is exactly the anti-alias low-pass that decimation needs. A polynomial cannot low-pass at all, which is the argument for this family that the THD numbers alone do not make.
  - **16 taps is the measured knee**, not a guess. Quality/cost at 10 kHz: 8 taps −73.6 dB, **16 taps −92.8 dB**, 32 taps −101.2 dB, 64 taps −99.1 dB. 64 is *worse* than 32 — past that the table's own linear interpolation becomes the floor. CPU on the real voice at +2.5%: Catmull-Rom 14.2 ns/sample, sinc-16 162.2 ns. Worst case (4 decks × 8 voices = 32 voices) is **1328 µs of the 5333 µs block budget, 24.9%**; 32 taps would put it near 50%, and ~85% at rate 2.0, which leaves no jitter margin. At rate 1.0 sinc is *faster* than the cubic (10.7 vs 13.3 ns) because the short-circuit skips the polynomial arithmetic.
  - **Rate 1.0 remains the bit-exact identity**, deliberately and by an explicit branch. A windowed sinc has `h(0) < 1` and `h(±1) ≠ 0`, so convolving at an integer position is a mild low-pass rather than a copy — without the short-circuit, "transparent at unity" would have quietly become a filter. `resample::test_raw_kernel_is_not_identity_at_integer_positions` pins the premise so the branch cannot rot into dead code, and `test_rate_one_is_bit_exact_identity` pins the result.
  - **Known limit: 16 taps means a wide transition band, so large pitch-up costs top end.** At rate 2.0 a 10 kHz source component is 2.98 dB down (the anti-alias cutoff has moved to `0.90/2` of Nyquist and 10 kHz sits in the transition). Zero droop across the DJ tempo range (±8%) and at moderate key shifts — measured 0.00 dB at +2.5% and −4 semitones. The alias suppression at rates just above 1.5 is correspondingly partial: −22 dB at rate 1.6, −52 dB at 1.8, −91 dB at 2.0. Sharpening that is what the 32-tap option buys, and it was declined on the CPU numbers above.
  - **Rates above 4.0 are not anti-aliased.** The tap count scales with the stretch, so `MAX_STRETCH` clamps it — `playback_rate` is reachable from MIDI note transposition and an unclamped rate would make the inner loop unbounded on the audio thread. Two octaves up gets full treatment at a bounded 64 reads per output sample; beyond that aliasing returns, traded deliberately against an unbounded RT cost.
  - **The golden master render is byte-identical, and that is a coverage gap, not a reassurance.** Every deck in that fixture plays at rate 1.0 (track BPM equals transport BPM), so it goes through the short-circuit and cannot see the resampler at all. It did not need regenerating and **no listening debt is incurred by the fixture** — but the change does alter what the console sounds like whenever tempo sync is engaged, which nothing in the golden path exercises. A human listen on a tempo-synced mix is owed on the change itself. Three other fixtures already carry a separate listen debt.
  - `InterpolationType::Lagrange` is misnamed — the coefficients (`c2 = 0.5·(p2−p0)`) are Catmull-Rom, i.e. cubic Hermite with neighbour-estimated tangents, not the 4-point Lagrange polynomial (which measures ~5 dB better). The name is kept because the discriminant is a wire value that `granular.rs` maps parameter 1 onto; both legacy kernels are retained for A/B measurement.
- **Action-to-sound latency is 7.4 ms and fully accounted for** (re-measured 2026-07-30, `conductor/examples/probe_deck_latency.rs`; 256-frame block at 48 kHz). An impulse fed to a deck emerges at master after **353 samples**, which decomposes exactly: **256 (the block itself) + 96 (limiter look-ahead, 2 ms) + ~1 (onset-detection quantisation)**. There is no unexplained latency left in the console. Throughput is separately healthy — 5 minutes on real ALSA hardware with **0 backend xruns**.
  - **This was 28.7 ms until the source insert slots landed, and older notes quote that figure.** Every deck chain used to carry a `KeySync` phase vocoder unconditionally — a 1024-point FFT window (21.3 ms) running on every block to serve a KEY latch that **defaults to off**. The chain is now `Sampler → [pitch slot] → [dna slot] → Gain → Biquad → StereoUtility → [fx slot] → DjIsolator`, where the slots hold `ProcessorTypeId::BYPASS` until the operator engages something (`TopologyCommand::SwapProcessor`, which preserves routing). Holding a slot open costs one buffer copy and zero latency. **If you are quoting 28.7 ms, you are quoting the pre-slot console** — re-run the probe.
  - **The limiter's look-ahead was the last undeclared latency.** `LimiterProcessor` writes at `write_pos` and reads at `write_pos - lookahead_samples`, a genuine 96-frame delay line, but inherited the trait default `latency_samples() -> 0` — every FFT-based processor declared, and the one with a *delay line* rather than a *window* was missed. Now declared. It sits at the end of the master chain so PDC has nothing to realign against it and the golden render is unchanged; the value of declaring it is that the probe's "undeclared" figure now reads as pure block quantisation, so the next real omission stands out instead of hiding inside a 353-sample gap.
  - **Until 2026-07-29 the graph believed all of this was zero.** `KeySync` and `DnaMorpher` both ran `SpectralPipeline` while inheriting the trait default `latency_samples() -> 0`, so `CompiledGraphPlan.node_latencies` summed to 0 across the whole console and PDC aligned nothing. Both now declare. `KeySync` is unconditional; `DnaMorpher` is **conditional** (0 while disengaged, `fft_size` once engaged) because it returns a bit-transparent copy before `engaged` — and since `latency_samples()` is polled at topology-compile time (`graph/mod.rs:121`) and **not per block**, engaging DNA morphing mid-session gains 21.3 ms that PDC never learns about. That hazard is documented on the method and belongs to 6.4, which is what first makes it reachable.
- **Cost-gated parallelism**: `execute_stage` dispatches a stage to the worker pool only when it has ≥ 2 nodes and its telemetry-measured cost exceeds `TaskPool::parallel_threshold_cycles`; otherwise it runs inline on the RT thread. The default worker count is `available_parallelism() - 1` (an upper bound — spare workers park), and the gate is self-calibrating (cold start = serial, escalating only proven-heavy stages). This is why small graphs and cheap stages show no pool activity — dispatch overhead exceeds their work. Tunable via `NULLHERZ_WORKERS` and `NULLHERZ_PARALLEL_THRESHOLD_CYCLES`; measured with `cargo run --release -p nullherz-conductor --example bench_console_block`.
- **The pool pays off at OFFLINE block sizes, not live ones** (measured 2026-07-29, 4-core box @ 3.28 GHz, no `isolcpus`, 8000 blocks per configuration, bootstrapped 4-deck console). **Benchmark it at 256 and you will wrongly conclude the pool is dead weight** — that is the trap this note exists to prevent.

  | block | budget | serial mean | gated (default) | forced (`THRESHOLD=0`) |
  | ---: | ---: | ---: | ---: | ---: |
  | 256 | 5333 µs | 117 µs | ~equal to serial (gate never fires) | 140 µs — **worse** |
  | 1024 | 21333 µs | 377 µs | **350 µs (−7%)** | 412 µs — worse |

  Two separate findings:

  1. **At 256 samples the gate never fires**, because the *whole* 34-node graph costs ~126 µs spread across many stages, and one stage must exceed `parallel_threshold_cycles` (150k cycles ≈ **46 µs** at 3.28 GHz) on its own. "Pool on" and "pool off" are therefore the same code path at DJ latency. This is correct behaviour, not a missing switch.
  2. **At 1024 samples it fires and wins** — 7% mean, 6% median, 12% better p99 than serial. It also beats FORCED parallelism (350 vs 412 µs), because the gate parallelizes only the stages worth it and leaves cheap ones inline. `bounce.rs` renders at `MAX_BLOCK_SIZE`, so **the offline bounce path is getting this today.**

  The reason block size is the whole variable: forced-parallel p99.9 is roughly **constant in absolute terms** across block sizes (2662 µs at 256, 1900 µs at 512, 2410 µs at 1024) — it is dispatch and scheduler-wakeup jitter, a fixed cost, not proportional to the work. Measured against the deadline it becomes 50% → 18% → 11% of budget. The pool does not get better at large blocks; **the deadline gets more forgiving.** That is also why the pool cannot help at DJ latency without core isolation (`isolcpus`/`nohz_full`) attacking the jitter itself — see roadmap 1.2, which notes the reference machine has none, so pinning reserves nothing.

  Expect the gate to start firing at live block sizes only when a single stage exceeds ~46 µs: the Phase 5 tap bus (16 spectral taps, one FFT each) and convolution nodes (6.9) are the first planned candidates.
- **Failure containment**: `SidecarSupervisor` watches SHM heartbeats; a stall (>200 ms) swaps in `FallbackProcessor` at the failed node's `node_idx`, and repeated failure can trigger global Safe Mode via the command bus.
- **Boot sequence** (`conductor/main.rs`): load `system_config.json` → resolve backend (fallback: Threaded) → start engine → spawn WebSocket gateway → bootstrap 4-channel DJ mixer topology → start MIDI sidecar bridge.

## 5. Verification Infrastructure

- **~360 `#[test]` functions** across the workspace (green in both profiles, verified 2026-07-28). **Timing assertions are release-only**: `long_track_control_path_test` measures the control path against the 5.8 ms audio-block budget, which an unoptimized build misses on merit — it failed at 6.13 ms under `cargo test --workspace` (debug) while passing in release, i.e. the documented gate cried wolf. Those assertions now compile in only when `debug_assertions` is off, the profile-independent *ratio* invariant (cost flat in track length) is asserted in both, and the `test-release` CI job is what actually enforces the budgets. **Test isolation** (`conductor/tests/test_isolation_gate_test.rs`): tests must not open the real `library.redb`. Six call sites did — five via `Conductor::new()`, one via `OfflineRenderer::new()` one level down — and it failed silently, because redb's exclusive lock makes `with_library_path` substitute a private fallback rather than error. Under `cargo test --workspace` (parallel binaries) the outcome was a race: first opener got the developer's 233 MB library, the rest got empty ones, so the same test saw two different worlds depending on scheduling, and the losers left `fallback_*.redb` litter behind (25 had accumulated). Tests now take `":memory:"`, the fallback branch announces itself, and the suite is hermetic — verified by hashing the working tree across a full run. The 1-in-5 abort that prompted this was never reproduced under capture (17 consecutive clean runs since), so it is not confirmed to be the same defect.
